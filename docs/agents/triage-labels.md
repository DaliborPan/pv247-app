# Triage labels

Use these mappings for Matt Pocock's triage roles in the GitHub issue tracker.

## Categories

| Role | GitHub label | Meaning |
| --- | --- | --- |
| `bug` | `bug` | Existing behavior is broken |
| `enhancement` | `enhancement` | New feature or improvement |

## States

| Role | GitHub label | Meaning |
| --- | --- | --- |
| `needs-triage` | `needs-triage` | Awaiting maintainer evaluation |
| `needs-info` | `needs-info` | Awaiting clarification from the reporter |
| `ready-for-agent` | `ready-for-agent` | Fully specified and ready for agent implementation |
| `ready-for-human` | `ready-for-human` | Requires human implementation or judgment |
| `wontfix` | `wontfix` | Will not be actioned |

A triaged issue has exactly one category and one state from these tables. Replace the previous state label when transitioning; preserve unrelated labels. Follow `triage` for transitions and confirmation requirements. Other existing labels, such as `question`, do not substitute for these states.
