## Course information

### Team

Our tutoring team is made up of developers from FI MUNI partner company InQool a.s. Most of us are FI alumni and each week a different duo will teach.

### Communication

As a main channel for communication, we will use our discord server (not MUNI). You can also contact us via faculty emails, but there is a high chance that you will get your answers much quicker in the chat group. You will receive discord invite link in your faculty email.

### Seminars

Each seminar will consist of two parts. The first part (up to 2 hours) will be dedicated to explaining the current week's topics. In the second part of the seminar, you will be solving the current week's assignments (more on those later). Also don't be afraid to ask questions, especially during the second half of the seminar.

### Evaluation

To pass the course, you must fulfill **three requirements**: attending classes, completing weekly assignments, and working on a team project.

#### Attendance

Course attendance is mandatory. Each student is allowed to have two unexcused lesson.

#### Weekly assignments

- You can earn a maximum of **210 points** from weekly assignments, with each assignment being worth between 10 and 40 points.
- Additional points may be awarded for active participation, such as well-structured or efficient solutions, engagement during lectures, and contributions to discussions on Discord.

At least **130 points** are required.

#### Team project

The team project is graded on a pass/fail basis ...don’t worry! :) After presenting your project, you’ll receive either a pass or a fail. If you don’t pass, you’ll have the opportunity to address the issues and resubmit.

### Weekly assignments

For (almost) every lecture there will be a weekly assignment for you to do. You always have 1 week to solve it (deadline is at midnight the night before next lecture).

#### Getting your repository

To work on assignments you need a GitHub account. Open the relevant homework in the application and choose **Create repository**. GitHub will create a private repository from the assignment template.

> **IMPORTANT!** Wait at least one minute after creating the repository, then choose **Finish setup**. Once setup is complete, you will receive a GitHub invitation and can open your repository from the homework card.

Instructions are provided in `README.md`. Clone the repository or use GitHub's built-in VS Code editor by pressing `.` or changing `.com` to `.dev` on the repository dashboard (read more about this feature [here](https://docs.github.com/en/codespaces/developing-in-codespaces/web-based-editor)).

#### Submitting the finished assignment

Create a branch named `solution` from `main` and implement your work there. When you are ready to submit, create a pull request from `solution` to `main`. Leave the pull request open and do not merge it.

The pull request must be open **before** the deadline. We will grade the latest commit pushed before the deadline.

You can push further changes to the same `solution` branch before the deadline; they will appear in the pull request automatically.

#### Feedback

After submissions close we will review your pull request using GitHub's review tools. Feel free to reply to comments and ask questions about the feedback.

### Team project

By the end of the semester, you will work on a team project—a web application that must fulfill the specified requirements.

#### Important dates

- **19. 10.** - Following the 6th lecture, start considering potential project topics and assembling your team.
- **2. 11.** - Submit your chosen project topic through this web application.
- **17/18. 11.** - After the final lecture, a brief project review will take place:
  - Each team must present their progress. By this point, around 10% of the project should be completed.
  - You should have a GitHub repository set up, a Next.js application initialized, and a clear concept of the features you plan to develop.
- **8/9. 12.** - Final project presentations will take place.

#### Base requirements

- Team of 3-4 students
- README.MD containing specification and scope of the project
- Presentation of the project (~15 min)
  - project overview and demo (~5 min)
  - highlight interesting parts of your code (used libraries, custom hooks etc.) (~5 min)
  - Q&A (~5 min)

#### Technological requirements

- All features implemented
- Git collaboration (each student must have a contribution to the codebase)
- Responsive design
- User authentication
- Server-side rendering alongside client-side rendering
- Database (CRUD operations)
- Proper metadata
- Hosted online (Vercel)
